# CodeAfar HarmonyOS NEXT V1 设计

**日期：** 2026-07-22  
**状态：** 已确认  
**目标平台：** HarmonyOS NEXT 原生应用，ArkTS、Stage 模型、ArkUI

## 1. 目标

交付一个原生 HarmonyOS NEXT 客户端，让用户在不部署 CodeAfar 云服务的前提下，从鸿蒙手机或平板安全地远程使用 Mac 上的 Claude Code 和 Codex。

鸿蒙端沿用现有 CodeAfar 产品规则：Provider 工作区隔离、新建会话时选择目录和权限、流式聊天、可复制消息、内部工具活动不进入普通聊天、语音只填写可编辑草稿且不自动发送。

V1 的成功标准是源码、自动化测试、可安装 HAP、鸿蒙模拟器验收和 Mac 侧安全验证全部通过。仅创建工程骨架不算交付。

## 2. 已确认的约束

- 不建设或运营 CodeAfar 中继、账号或数据服务。
- HarmonyOS NEXT 没有可依赖的 Tailscale 官方客户端，V1 不移植 Tailscale、WireGuard 或通用 VPN。
- Mac 使用 Tailscale Funnel 提供公网 HTTPS/WSS 入口；鸿蒙本身不是 Tailnet 节点。
- Funnel 只转发到 CodeAfar 的专用远程网关，不暴露本地聊天网页、管理页、诊断页或目录授权接口。
- UI 使用原生 ArkUI，不使用 ArkWeb 承载聊天主体。
- 语音没有可验证的端侧保证时必须显示不可用，不允许回退到云端识别。
- 当前开发机尚未安装 DevEco Studio 和 HarmonyOS SDK；实施阶段首先补齐并验证官方开发环境。

## 3. 非目标

V1 不包含：

- 鸿蒙通用 Tailscale、WireGuard、VPN、出口节点或子网路由功能。
- CodeAfar 自建公网中继、云端账号、云端历史或推送服务。
- 云端语音识别、随应用打包的自有语音模型、音频上传或语音自动发送。
- 在鸿蒙端浏览或授权 Mac 文件系统；鸿蒙只能选择 Mac 已授权的项目。
- 文件上传、图片输入、富文本工具详情面板或多 Agent 编排。
- AppGallery 正式发布、商用签名和审核材料；V1 交付可安装的开发/测试 HAP 与完整源码。

## 4. 总体架构

```text
HarmonyOS NEXT CodeAfar
  ├─ ArkUI 页面与导航
  ├─ ArkTS 状态与协议层
  ├─ WSS 客户端、自动重连
  ├─ 安全凭据存储
  └─ 严格端侧语音适配器
                 │
                 │ TLS/WSS + Device Token
                 ▼
          Tailscale Funnel
                 │
                 ▼
Mac 127.0.0.1 专用远程网关
  ├─ 配对端点
  ├─ WebSocket 会话协议
  ├─ 认证、限速、大小限制
  └─ 现有 CodeAfar Engine
```

Harmony 客户端复用现有 JSON WebSocket 协议和产品语义，不复用网页 DOM。Mac Engine 继续拥有会话、项目授权、Provider、权限和历史的唯一真实状态。

## 5. Mac 远程入口与 Funnel 管理

### 5.1 独立远程网关

Mac 新增只监听 loopback 的独立远程网关端口，与现有桌面 UI/管理服务分离。网关只注册：

- `POST /pair`：一次性配对码换取设备凭据。
- `GET /ws`：通过 Device Token 认证后升级为现有 WebSocket 协议。
- `GET /healthz`：不含版本、目录、设备或会话信息的最小存活检查。

其他路径一律返回 404。网关不注册 `/admin`、`/desktop/projects`、静态网页或诊断路由。即使 Funnel 配置错误，也不能通过该监听器访问本地管理能力。

### 5.2 Funnel 生命周期

Mac 设置页增加“鸿蒙远程访问”开关。用户主动启用后：

1. 检测 `tailscale` CLI 是否存在、当前节点是否登录、Funnel 是否可用。
2. 查询现有 Funnel 配置，选择 CodeAfar 专用的 8443 端口；如端口已被用户配置占用，不覆盖并给出明确说明。
3. 以后台模式把 Funnel 8443 转发到专用 loopback 网关。
4. 保存 CodeAfar 创建的最小配置指纹，用于状态核对和安全清理。
5. 关闭功能时只删除 CodeAfar 自己创建且仍匹配指纹的配置，不修改用户的其他 Serve/Funnel 项目。

Mac 应用不静默启用公网入口。Tailscale 未安装、未登录、策略禁止 Funnel、证书未就绪或 CLI 版本不兼容时，界面显示可执行的修复说明，不泄露原始命令输出。

### 5.3 配对

Mac 生成密码学安全的一次性配对码并显示二维码。配对码满足：

- 仅保存摘要，不保存明文。
- 五分钟失效、成功一次后立即删除。
- 限制总尝试次数和来源请求频率。
- 不放入 HTTP 查询参数；二维码内包含 Funnel 端点和配对码，鸿蒙在请求体发送。

配对成功后 Mac 为该设备生成独立的高熵 Device Token，Engine 只保存可验证形式和设备名称。鸿蒙把 Token 写入 HarmonyOS 安全凭据存储。每台设备可单独命名、查看最近在线时间和撤销；撤销后现有连接断开，后续认证立即失败。

## 6. HarmonyOS 工程结构

```text
harmony/
  ├─ AppScope/
  ├─ entry/src/main/ets/
  │   ├─ pages/          配对、会话、聊天、设置
  │   ├─ components/     Provider 切换、消息、输入器、新会话面板
  │   ├─ protocol/       收发消息模型与严格解码
  │   ├─ networking/     WSS、认证、退避重连、前后台生命周期
  │   ├─ stores/         Connection、Session、Chat、Settings
  │   ├─ security/       Token 安全存取
  │   └─ speech/         端侧语音能力接口与系统适配
  └─ entry/src/ohosTest/ 自动化测试
```

各模块只依赖明确接口：页面不直接操作 WebSocket，Store 不直接读取安全存储，协议解码不修改 UI 状态，语音控制器只返回草稿文本和状态。

## 7. 状态与数据流

### 7.1 连接

启动时从安全存储读取端点和 Device Token，完成 TLS 校验后建立 WSS。认证成功才请求 Provider、项目、会话和模板列表。网络切换或短暂断线采用有上限的指数退避；进入前台立即尝试恢复，后台停止持续重试和语音录制。

协议版本不兼容、证书失败、Token 被撤销和 Mac 离线分别映射为不同用户提示。TLS 或认证失败不得降级到明文 WebSocket。

### 7.2 Provider 工作区

顶部同一行显示 `Claude | Codex` 和新建按钮。会话列表只展示当前 Provider；每个 Provider 单独记住最近会话。切换时恢复该 Provider 最近会话，没有历史则进入未提交的新会话草稿。

已创建会话的 Provider 固定。Provider 不可用时禁用入口并显示原因；当前 Provider 变为不可用时切换到第一个可用 Provider，不能继续展示另一个 Provider 的会话。

### 7.3 新建会话与首条消息

点击新建只创建本地草稿。面板显示 Mac 已授权项目和当前 Provider 的权限模式，不重复提供 Provider 选择。用户第一次发送时，客户端以稳定 `requestId` 请求创建会话；收到匹配的 `session_created` 后才发送同一条首消息，并等待 `text_accepted`。断线重试复用原 request ID，避免重复会话或重复执行。

### 7.4 聊天

聊天页渲染用户文本、Assistant 流式文本、排队状态和可理解错误。`tool_use` 事件仍可由协议接收并保留在后端历史，但普通聊天不创建工具消息或展示命令参数。

输入器固定在底部。软键盘发送动作和发送按钮走同一提交函数；换行不发送。消息支持系统文本选择和一键复制。断线保留未发送草稿，成功发送后才清空。

## 8. 界面与自适应

- 手机竖屏：会话列表与聊天使用导航页面切换。
- 平板或横屏：左侧 Provider/历史，右侧聊天的双栏布局。
- 新建会话使用原生底部面板或对话框，目录选择控件必须实际列出 Mac 返回的项目。
- 顶部连接状态只显示“已连接、连接中、需要重新配对、Mac 离线”等用户语义。
- 权限标签来自 Provider 描述，不在鸿蒙端硬编码 Claude/Codex 内部参数。
- 颜色、字号、触摸区域、焦点和屏幕阅读器标签遵循 HarmonyOS 设计与无障碍能力。

## 9. 语音输入

语音作为输入法，不是新的协议消息类型。`SpeechController` 暴露空闲、请求权限、准备、监听、处理、不可用和失败状态，并只回调当前语音片段文本。

生产适配器必须同时满足：

1. 官方 SDK/API 明确提供端侧或离线执行保证。
2. 当前设备和语言运行时报告支持。
3. 用户已授予麦克风及必要的语音权限。

任何条件不满足都显示“当前设备或语言不支持离线语音输入”，不尝试云端接口。官方 Core Speech Kit 若无法从 API 和文档验证端侧保证，不得接入生产路径。

开始录音时保存原草稿；部分结果只替换本轮语音片段，不覆盖用户原有文字。最终结果仍停留在输入框，必须由用户主动发送。第二次点击、离开聊天、进入后台、权限撤销、错误或完成都必须释放麦克风资源。

## 10. 安全与隐私

- Funnel TLS 证书必须通过系统信任校验；禁止忽略证书错误。
- 远程网关设置帧大小、请求体大小、认证超时、连接数和速率上限。
- 未认证连接不能请求任何 Provider、项目、会话或健康详情。
- 配对码、Device Token、语音、草稿、项目路径和完整聊天不写日志。
- Token 不出现在 URL、崩溃报告、分析事件或普通配置文件中。
- Funnel 中继无法替代应用认证；公网端点始终要求一次性配对或有效 Device Token。
- 本地桌面管理 token 永不通过远程网关发送。
- 关闭远程访问后停止新连接并关闭现有远程连接，再移除 CodeAfar 所属 Funnel 配置。

## 11. 错误处理

错误分为连接、配对、认证、协议、Provider、会话、权限和语音八类。UI 显示下一步动作，不直接显示 shell 命令、JSON 参数或内部错误堆栈。

- Funnel 不可用：回到 Mac 检查远程访问设置。
- Mac 离线：保留草稿并提供重试。
- Token 无效或撤销：清除本地凭据并进入重新配对。
- Provider 不可用：禁用对应工作区并显示 Mac 返回的用户说明。
- 首条消息创建失败：保留项目、权限和提示词，可用同一 request ID 重试。
- 权限更新失败：恢复服务器确认的权限状态。
- 语音不可用：文字输入继续可用，不阻断聊天。

## 12. 测试与验收

### 12.1 自动化测试

- ArkTS 协议测试：完整消息解码、未知字段、错误类型和协议版本。
- Store 测试：Provider 过滤/恢复、草稿、首条消息去重、重连和权限回滚。
- 网络测试：认证顺序、退避上限、前后台切换、Token 撤销。
- 语音策略测试：端侧能力门禁、草稿合并、权限拒绝和资源释放。
- ArkUI 测试：配对、Provider 切换、新建会话、聊天、复制和错误页面。
- Go 测试：远程路由白名单、配对过期/单次使用、限速、撤销、管理接口隔离。
- 跨平台契约测试：Harmony、iOS、Android 对 Provider、会话和工具隐藏规则一致。

### 12.2 集成验收

在鸿蒙模拟器上完成构建、安装、页面和协议测试；Funnel、扫码、麦克风和前后台生命周期还需在支持的真实 HarmonyOS NEXT 设备上完成硬件验收。若当前没有真实设备，必须明确保留硬件验收项，不能把模拟器通过表述为真实设备交付。

完整验收至少覆盖：

- 扫码配对、配对码重放失败、设备撤销后断线。
- Claude/Codex 切换、历史隔离、分别恢复及不可用 Provider。
- 新建会话、目录选择、所有权限模式和首条消息断线重试。
- 流式回复、Return/软键盘发送、换行、复制、工具事件隐藏。
- Mac/Funnel 离线、网络切换、后台恢复和协议不兼容。
- 语音权限拒绝、端侧能力缺失、连续点击、后台停止和不自动发送。
- 通过 Funnel 请求管理、诊断、目录授权和静态页面全部失败。

## 14. 参考依据

- HarmonyOS NEXT 官方推荐 ArkTS、ArkUI 和 Stage 模型。
- HarmonyOS SDK 提供 Network Kit、WebSocket、关键资产安全存储和 Core Speech Kit。
- Tailscale 官方安装平台不包含 HarmonyOS；V1 不把非官方移植作为产品依赖。
- Tailscale Funnel 可把公网 TLS 流量转发到 Mac 本地服务，且不要求访问端安装 Tailscale。
